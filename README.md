# PyMOP TSE Artifact

Artifact for *A Generic and Efficient Runtime Verification System for Python and its Large-scale Evaluation*.

[PyMOP](https://github.com/SoftEngResearch/pymop) is maintained in a separate repository. This repository contains the paper's appendix and the evaluation data.

## Appendix

[`appendix.pdf`](appendix.pdf) contains the supplementary material for the paper:

- Comparison of the three instrumentation strategies
- Documentation keywords and extraction patterns used to mine API specifications

## Data

The CSV files under [`data/`](data/) follow Section IV and Section V of the paper. Each `results.csv` row is one project under one configuration. It records pytest outcomes, instrumentation and monitoring time, peak memory, and counts of violations, monitors, and events. `consistent-results.csv`, where present, keeps projects whose test outcomes stayed consistent with the unmonitored baseline.

### Evaluation subjects

The 3,356 projects used throughout the evaluation are in [`data/evaluation-subjects/`](data/evaluation-subjects/):

- [`projects.csv`](data/evaluation-subjects/projects.csv): `owner/repo` and commit SHA, with no header row
- [`project_stats.csv`](data/evaluation-subjects/project_stats.csv): SLOC, stars, age in years, and commit count from Table I of the paper

### RQ1: How does PyMOP compare vs. DyLin and DynaPyt?

In [`data/rq1-pymop-dylin-dynapyt/`](data/rq1-pymop-dylin-dynapyt/):

- [`results.csv`](data/rq1-pymop-dylin-dynapyt/results.csv): PyMOP, DyLin, and DynaPyt on the same projects, with and without library monitoring

### RQ2: What are PyMOP's runtime and memory overheads?

In [`data/rq2-runtime-memory-overhead/`](data/rq2-runtime-memory-overhead/):

- [`results.csv`](data/rq2-runtime-memory-overhead/results.csv): algorithm D⟨X⟩ with and without library monitoring, against the unmonitored baseline
- [`correlation_results.csv`](data/rq2-runtime-memory-overhead/correlation_results.csv): the sample of 1,000 projects used for the overhead correlation analysis

### RQ3: How effective is PyMOP for finding real-world bugs?

In [`data/rq3-bug-finding/`](data/rq3-bug-finding/):

- [`pr_status.csv`](data/rq3-bug-finding/pr_status.csv): pull requests and issues filed for inspected violations
- [`README.md`](data/rq3-bug-finding/README.md): how to read `pr_status.csv`

### RQ4: How relevant is the choice of monitoring algorithms?

B⟨X⟩, C⟨X⟩, C+⟨X⟩, and D⟨X⟩, in [`data/rq4-monitoring-algorithms/`](data/rq4-monitoring-algorithms/):

- [`results.csv`](data/rq4-monitoring-algorithms/results.csv): the unmonitored baseline and B⟨X⟩, C⟨X⟩, C+⟨X⟩, and D⟨X⟩ on all 3,356 projects, with libraries monitored
- [`consistent-results.csv`](data/rq4-monitoring-algorithms/consistent-results.csv): the 2,808 projects on which all four algorithms succeeded

### RQ5: How do instrumentation strategies compare?

Monkey patching, monkey patching plus curses, and monkey patching plus AST rewriting, all monitored with D⟨X⟩, in [`data/rq5-instrumentation-strategies/`](data/rq5-instrumentation-strategies/):

- [`results.csv`](data/rq5-instrumentation-strategies/results.csv): the unmonitored baseline and each strategy (`monkey patching`, `curse`, `ast`, and `ast_full`) on all 3,356 projects, monitored with D⟨X⟩
- [`consistent-results.csv`](data/rq5-instrumentation-strategies/consistent-results.csv): projects whose test outcomes stayed consistent with the unmonitored baseline

### RQ6: How beneficial is unit test generation for PyMOP?

PyMOP runs on developer-written tests and on tests generated by Pynguin, in [`data/rq6-test-generation/`](data/rq6-test-generation/):

- [`results.csv`](data/rq6-test-generation/results.csv): developer-written tests and Pynguin-generated tests, each with and without D⟨X⟩ (`Original`, `Original_D`, `Testgen`, `Testgen_D`), on the 1,701 projects where Pynguin ran, including statement coverage
- [`pr_status.csv`](data/rq6-test-generation/pr_status.csv): pull requests and issues filed for inspected violations from generated tests

### Discussion

- [`data/offline-monitoring/results.csv`](data/offline-monitoring/results.csv): offline algorithm A⟨X⟩ against the online algorithms on the 227 projects that finished
- [`data/monitor-garbage-collection/results.csv`](data/monitor-garbage-collection/results.csv): D⟨X⟩ with and without monitor garbage collection on 3,102 projects
